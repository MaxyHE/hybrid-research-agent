# Hybrid research progress and cancellation

Hybrid research reports its current stage as it plans, searches, reads sources,
organizes evidence, and writes the report. Updates include research-task, source,
and model-request counts. These are execution events, not a time estimate;
model-request counts describe requests entering the invocation boundary and may
include a request cancelled before it reaches the provider. Existing percentage
milestones remain in place. Raw prompts and evidence text are excluded from these
progress messages.

Cancellation is cooperative. An in-flight provider request may finish before the
run observes cancellation; subsequent model and retrieval work stops at execution
boundaries. Threads are not forcibly killed.

When execution is cancelled, the server attempts to retain `trace.jsonl`,
`sources.json`, available `source_snapshots`, and `run.json` in the run's artifact
directory. The record uses `suspended`, `user_cancelled`, and `resumable: false`.
It contains the notes already collected and any available located evidence
packets. Responses from a partially finished parallel batch remain in the trace,
even if the batch has not yet contributed to the collected notes. No successful
report is generated by cancellation handling. Archive-write errors are logged
without replacing the cancellation outcome.

These files support inspection of work already performed. Automatic resume is
not implemented. The same cancellation and progress bridge applies to the
configured default, Qwen, and located-evidence routes.

Live Hybrid stage events retain their execution counters in Socket updates.
Refreshing a cancelled run shows its terminated status and labels the prior
progress message as the last record before termination. The local Hybrid launch
script initializes the same milestone logging and log processing used by the
standard Web entry point.

Queued research receives the application context needed by its background worker.
After a running task releases its user slot, the next queued task can execute
through the same research service. Model-provider choices describe supported
connections; configure the service address and credentials before first use.
